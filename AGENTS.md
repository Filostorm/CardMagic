# Repository Agent Instructions

- Use more technical language than the user does so they can learn precise terms and write better prompts.
- If you notice unrelated errors, fix them when the fix is low-risk and does not require a breaking upgrade or destructive action.
- Never generate frame textures unless the user explicitly asks for generated textures.
- Use existing MSE/source-pack assets as the authoritative source for frame textures, pinlines, masks, and blend assets.
- After every code patch, update the Expo production deployment with the existing production deploy command when credentials and environment allow it. In this repo, prefer `npm run deploy:web`.
- Before production deployment, increment the app version in both `package.json` and `app.json` using semantic-versioning scale:
  - Large feature: increment the major version by `1.0.0`.
  - Small feature: increment the minor version by `0.1.0`.
  - Bug fix or visual tweak: increment the patch version by `0.0.1`.
- If deployment or versioning cannot be completed, report the blocker explicitly in the final response.

## MSE Frame Asset and Compositing Notes

- Treat the local MSE source pack and the checked-in MSE renderer outputs as the authority for frame behavior:
  - Source-pack assets: `assets/card-assets/basic-m15/source-pack/data/`
  - Renderer-ready assets: `assets/card-assets/basic-m15/mse-renderer/`
  - Main MSE style reference in Downloads, when present: `/Users/josiahmann/Downloads/Basic-M15-Magic-Pack-main/data/`
- Do not infer or invent frame texture geometry. Before changing frame rendering, inspect the relevant MSE style script and source assets with `rg`/`find`.
- The MSE blend utility reference is `/Users/josiahmann/Downloads/Basic-M15-Magic-Pack-main/data/magic-blends.mse-include/new-blends` when present. The key function is `color_background(...)`.
- Standard multicolor creature/main frames are not generated by runtime drawing. This app uses precomposited MSE renderer bitmaps from:
  - `assets/card-assets/basic-m15/mse-renderer/mainframes/standard-composited/multicolor/`
  - `assets/card-assets/basic-m15/mse-renderer/mainframes/standard-composited/hybrid/`
  - The selector is `getMseM15ColorBlend(...)` in `src/data/mse-frame-blends.ts`, then `getMseM15MainframeSource(...)` in `src/data/mse-frame-renderer.ts`.
- Colored artifacts must follow MSE's masked blend model, not a separate generated pinline model:
  - MSE logic: `masked_blend(mask: artifact_blend_card.png, dark: template("a"), light: base)`.
  - In this app, render the artifact base frame first, then overlay the resolved colored or multicolor full mainframe through `artifact_blend_card.png`.
  - The mask is `assets/card-assets/basic-m15/source-pack/data/magic-modules.mse-include/cards/375 m15 simple/artifact_blend_card.png`.
  - The app implementation is `MseArtifactMainframeBlendOverlay` in `src/components/card-preview.tsx`, using `getMseM15ArtifactMainframeBlendMaskSource()` from `src/data/mse-frame-renderer.ts`.
- Separate pinline assets do exist, but they are not the authoritative implementation for colored M15 artifact mainframes:
  - `assets/card-assets/basic-m15/source-pack/data/magic-modules.mse-include/pinlines/744x1039/m15/`
  - Use them only when the target MSE style actually references the separate pinline pipeline, or when explicitly experimenting.
- Rare/security stamp backing should use the MSE stamp backing assets, including colored artifact backing when applicable:
  - `assets/card-assets/basic-m15/mse-renderer/stamps/security-backing/`
  - `getMseM15StandardColorSecurityStampBackingSource(...)` handles colored standard stamp backing.
